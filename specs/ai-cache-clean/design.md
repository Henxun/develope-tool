## 0. 设计意图

**目标用户**：本机同时装着多个 AI 编码工具的开发者（Claude Code、Codex CLI、Cursor…）。磁盘被 `~/.claude`、`~/.codex`、Cursor 的 Cache 目录吃掉，但不知道哪个工具吃了多少、哪些能删。

**真正的问题不是"清理"，而是"敢不敢删"**：这些目录里混着会话记录、登录凭据和纯垃圾。所以设计重心按顺序是：

1. **先看清账** —— 按工具分组，逐项标安全/谨慎/危险，体积一眼可比；
2. **再动手** —— 默认只勾安全项，危险项必须手动勾；
3. **最后确认** —— 二次确认弹窗把"不可恢复"和危险项放在视觉第一层。

**一句话视觉方向：「磁盘账本」** —— 每张工具卡像一页账目：顶部一条用工具色着色的占比条，中间是可勾选的明细行，右侧是金额（体积）。整体延续现有页面的"浅色玻璃卡片 + 深青强调色 + 柔和渐变背景"，不引入新的配色体系。

**关键视觉选择（评审重点）**：

- 主操作沿用 `var(--accent)`（#11617d 深青）；**页面上唯一常驻的 rose 实心按钮是「清理选中」**，破坏性操作全局唯一识别。
- 复用 disk-heatmap 的柔彩分类色板作为"工具身份色"，只以小色点（10px）和占比条（3px）出现，不铺满卡片 —— 既和现有页面同源，又不会让新页面变成调色盘。
- 统计块直接复用 disk-heatmap 的 4 列 stats 网格，和最近改动的页面视觉衔接。
- 确认弹窗**默认焦点落在「取消」**，回车不会误删。

## 1. 页面结构

### 1.1 整体骨架（桌面 ≥1024，设计基准 1280×800）

```
tools/layout 顶栏（既有导航，不改）
└── main 主卡：rounded-3xl / border-[var(--card-border)] / bg-[var(--card)]
    │        / p-6 sm:p-8 / backdrop-blur-xl / 现有投影
    ├── 1 页头        eyebrow + h1 + 一句话说明
    ├── 2 状态栏      [上次扫描 14:32 · 用时 1.2s]            [重新扫描]
    ├── 3 结果横幅（仅清理后出现）  已释放 3.4 GB     [×]
    ├── 4 统计块      可释放 3.4GB | 工具 3 | 缓存项 12 | 扫描耗时 1.2s
    ├── 5 工具分组列表（纵向堆叠，间距 12）  ToolGroupCard × N
    └── 6 操作条（sticky 底部）  已选 8 项 · 预计释放 2.1 GB   [清理选中]
（7）确认弹窗 / 清理进度 —— 覆盖层，见第 2 节
```

**容器选择说明**：沿用 `tool-data-migrate` 的"主卡 + 内部分区卡"结构（`rounded-3xl` 主卡、`rounded-2xl` 分区），因为本页同属"操作型工具页"；`disk-heatmap` 的无主卡结构是可视化工作台形态，不跟随。

**信息层级（权重从高到低）**：

1. 可释放总量（统计块第一块，最大字号）
2. 每个工具的体积与占比（卡头 + 占比条）
3. 单项明细（行：名称 / 路径 / 体积 / 风险）
4. 操作（sticky 操作条，始终可见）
5. 元信息（扫描耗时、时间、路径，11–12px 灰字）

### 1.2 工具分组卡（ToolGroupCard）

```
┌──────────────────────────────────────────────────────────────┐
│ ● Claude Code    macOS · 2.1 GB              [打开目录] [⌄]  │ 卡头 56px
│ ▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  3px 占比条  │
├──────────────────────────────────────────────────────────────┤
│ ☑  日志            ~/.claude/logs          412 MB    安全     │ 行 56px
│ ☐  会话记录        ~/.claude/projects      1.2 GB    谨慎     │
│ ☐  登录凭据        ~/.claude/.credentials    4 KB    危险     │
└──────────────────────────────────────────────────────────────┘
```

- 卡头左：10px 工具色圆点 + 工具名（16/600）+ 平台与总量（13/500 `slate-500`）。
- 卡头右：`打开目录`（12px 文字按钮，调既有 `reveal_in_file_manager`）、`⌄` 折叠（仅该组 ≥6 行时出现）；选中后卡头追加 `已选 2/3`（12px `slate-500`）。
- 占比条：高 3px、`rounded-full`、轨道 `bg-slate-200/60`、填充为工具色；宽度 = 该工具总量 / 全部工具总量；纯装饰 `aria-hidden`。
- 明细行：勾选框（20px）· 类别名（14/500）· 路径（11px mono `slate-400`，最大宽度 40%，截断并 `title` 全路径）· 体积（14/600 `tabular-nums`）· 风险徽标。整行可点击切换勾选，hover `bg-slate-50`，切换 `120ms`。
- 风险徽标：安全 = emerald、谨慎 = amber、危险 = rose（规格见 3.1）；危险行额外左侧 3px `rose-300` 竖条，常驻不依赖 hover。
- 组勾选规则：**卡头 checkbox 只覆盖该组"安全 + 谨慎"项**，三态（indeterminate）表示部分选中；危险项必须逐项手动勾选。理由：避免一次点击把"要重新登录"的项带进去。

### 1.3 操作条（StickyActionBar）

```
┌────────────────────────────────────────────────────────────────────┐
│ 已选 8 项 · 预计释放 2.1 GB        全选安全项  清除选择  [清理选中 8 项] │
└────────────────────────────────────────────────────────────────────┘
```

- `sticky bottom-4`、`rounded-2xl`、`border border-slate-200`、`bg-white/85`、`backdrop-blur-xl`、上投影 `shadow-[0_-8px_24px_-12px_rgba(15,23,42,0.18)]`，`px-4 py-3`。
- 主按钮 `清理选中 N 项`：**rose-600 实心 / hover rose-700 / h-10 / rounded-xl**，是整页唯一常驻危险色控件。
- 未选中时：按钮 disabled（`opacity-50 cursor-not-allowed`），左侧文案变 `请勾选要清理的缓存项`（`slate-500`）。
- 用 sticky 而非 fixed：滚到底部才固定，不遮挡首屏内容；主卡底部只留 `pb-6`。
- 窄屏（<640）：操作条两行 —— 第一行统计，第二行按钮全宽 `h-11`。

### 1.4 统计块

复用 disk-heatmap 的 `grid grid-cols-2 sm:grid-cols-4 gap-3`，每块 `rounded-xl border border-slate-200 bg-white/75 px-4 py-3 shadow-sm`：

| 位置 | 标签 | 值 | 备注 |
|---|---|---|---|
| 1 | 可释放空间 | 3.4 GB | 主指标，值 20/600 `tabular-nums`；左侧加 3px `var(--accent)` 竖条；下方 12px `共 12 项缓存` |
| 2 | 检测到的工具 | 3 个 | |
| 3 | 缓存项 | 12 项 | |
| 4 | 扫描耗时 | 1.2 s | |

清理完成后第 1 块标签改为 `剩余可释放`，与结果横幅的"已释放"区分，避免两个数字互相矛盾。

## 2. 状态设计

状态机：`idle → scanning → (results | empty | error) → confirming → cleaning → result → scanning(自动刷新)`。

### 2.1 初始态 / 首次进入

- 进入页面 **300ms 后自动开始扫描**（避开路由切换的卡片入场动画），满足"打开页面即扫描"的主流程。
- 扫描中不显示"开始扫描"按钮；页头右侧位置交给扫描状态与 `取消`。
- **不做跨会话持久化**：缓存大小变化快，每次进入都重新扫描，不展示"上次结果"。

### 2.2 扫描中（进度 + 骨架）

```
状态栏： ◌ 正在扫描 AI 工具缓存…   已找到 2 个工具 · 36 项          [取消]
统计块： 4 个骨架块（h-[68px] animate-pulse）
列表：   3 张骨架卡：卡头 24px 灰条 + 3 行 40px 灰条（宽 70% / 88% / 62%）
```

- **不造假百分比**：缓存扫描没有可靠分母，禁止用"进度 37%"这类假进度条。用 spinner（16px `animate-spin`，写法同 `tool-data-migrate`）+ 实时计数 + 骨架卡。
- 计数文案：`正在扫描 · 已找到 {toolsFound} 个工具 / {itemsFound} 项缓存`，由 Tauri 事件驱动，**节流 150ms 更新**，避免每事件 setState 抖动。
- 骨架结构与真实卡片一致，结果出现时布局不跳。
- `取消`：文字按钮；点击后前端忽略后续事件并进入"待扫描"态（页头下方显示 `扫描已取消` + `开始扫描` 按钮）。若后端无法中断，进度文案先显示 `正在停止…` 再落定。
- 扫描超过 8s，追加一行 12px `slate-400`：`缓存目录较大，扫描可能需要更久…`（不打断流程）。

### 2.3 有结果

- 统计块与工具卡列表淡入（120ms），底部操作条上移 8px 淡入（160ms）。
- **默认勾选规则**：安全项默认勾选、谨慎项默认不勾选、危险项始终默认不勾选。默认勾选让主流程"进入 → 扫描完 → 点一次清理"成立。
- 页头右侧 `取消` 替换为 `重新扫描`，旁边显示 `上次扫描 14:32`。

### 2.4 空态（没检测到任何 AI 工具）

```
┌─ 虚线卡：border-dashed border-slate-300 bg-white/60 rounded-2xl p-10 居中 ─┐
│                        [放大镜 / 机器人线性图标 40px slate-400]            │
│                        没有检测到 AI 工具的缓存                            │
│        常见位置里都没有找到缓存目录。先安装并运行一次 AI 工具，            │
│        再回来扫描。                                                       │
│   已检查：~/.claude · ~/.codex · ~/Library/Application Support/Cursor      │
│                    [重新扫描]      [查看支持的工具]                        │
└──────────────────────────────────────────────────────────────────────────┘
```

- "已检查路径"用 11px `font-mono` `slate-400`、`break-all`，让用户能判断是不是工具装在了别处。
- `查看支持的工具`：点击展开 12px 灰字清单（Claude Code、Codex CLI、Cursor、Gemini CLI、Continue、Aider、OpenCode）。
- 部分工具存在但缓存为 0 项：该工具折叠成一行灰条 `Claude Code — 未发现缓存`（12px `slate-400`，不可勾选），排在列表末尾。
- 空态不渲染操作条和统计块。

### 2.5 清理确认弹窗（重点：必须突出风险）

遮罩：`fixed inset-0 z-50 bg-slate-950/45 backdrop-blur-[2px] p-4 flex items-center justify-center`
面板：`w-full max-w-[520px] rounded-2xl border border-slate-200 bg-white shadow-[0_32px_80px_-24px_rgba(15,23,42,0.45)] overflow-hidden`

```
┌──────────────────────────────────────────────────────────────┐
│ [垃圾桶图标]  确认清理 12 项缓存？                 header p-5  │
│               3 个工具 · 预计释放 3.4 GB          border-b    │
├──────────────────────────────────────────────────────────────┤
│ 清理后无法恢复                                    body p-5    │
│ 这些缓存会在下次使用时由 AI 工具自动重新生成；                │
│ 已保存的对话、配置和项目代码不会被删除。                      │
│                                                              │
│ ⚠ 以下 2 项可能导致历史记录丢失：                 amber 区块   │
│    · Claude Code · 会话记录（1.2 GB）                         │
│    · Cursor · 本地编辑历史（86 MB）                           │
│                                                              │
│ ⛔ 以下 1 项清理后需要重新登录：                     rose 区块   │
│    · Claude Code · 登录凭据（4 KB）                           │
│                                                              │
│ 影响工具：Claude Code · Cursor · Codex CLI         12px chips  │
├──────────────────────────────────────────────────────────────┤
│ 清理期间请勿在 AI 工具中执行任务。       [取消] [确认清理 3.4 GB] │
└──────────────────────────────────────────────────────────────┘
```

**硬性规则（Coder 必须照做）**：

1. 主按钮是 **rose-600 实心**，文案必须带体积（`确认清理 3.4 GB`），让人看清代价；禁止用"确定 / OK / 是"。
2. **初始焦点在「取消」**，此时按 Enter 触发取消；Tab 才移动到危险按钮。Esc 与点击遮罩都等于取消。
3. `清理后无法恢复` 是 body 第一行、14px/600、`slate-900`，不允许塞进 12px 小字或灰色说明里。
4. 谨慎项用 amber-50 区块、危险项用 rose-50 区块，**分区列出**；没有某一级就整块不渲染（不显示空的分区标题）。
5. 必须同时给出"不删什么"来抵消恐惧：`已保存的对话、配置和项目代码不会被删除`。
6. 只选 1 项时标题用单数：`确认清理「会话记录」？`，并省略"影响工具" chips。
7. 体积数字 `tabular-nums`，确认过程中数字宽度不跳动。
8. 内容超高时 body `max-h-[60vh] overflow-y-auto`，header / footer 固定。

### 2.6 清理中

- 弹窗关闭，回到结果列表；行进入执行态：
  - 右侧状态胶囊：`待清理`（slate）→ `清理中`（accent 文字 + 12px spinner）→ `已清理`（emerald）/ `失败`（rose，`title` 显示原因）。
  - 正在处理的行 `bg-sky-50/50`；已清理行的体积加 `text-slate-400 line-through`。
- 操作条整体替换为进度区：`正在清理 3/12 · Claude Code · 会话记录`，下方 `h-1.5 rounded-full bg-slate-200` 轨道 + `bg-[var(--accent)]` 填充，宽度 `300ms ease-out`。
- **进度条不用 rose**：进度表示"工作中"，不是危险信号；危险语义只保留在确认动作上。
- 期间禁用所有 checkbox、`重新扫描`、`打开目录`。
- 单项失败不中断，继续下一项，累积到结果。

### 2.7 清理结果

```
┌─ 结果横幅：bg-emerald-50 / border-emerald-200 / rounded-2xl / p-5 ──────┐
│  已释放                                                        [×]     │
│  3.4 GB                                       40/44 600 tabular-nums   │
│  清理 12 项 · 3 个工具 · 用时 1.2 s                                    │
│  [重新扫描]    [在文件管理器中查看]                                     │
└────────────────────────────────────────────────────────────────────────┘
```

- 大数字 40/44/600 `tracking-tight tabular-nums`，单位 `GB` 用 20px `slate-600` 紧随其后。
- 有失败项：横幅下方接 amber-50 细条 `1 项未能清理：文件被占用（Claude Code · 日志）`，右侧放 `重新扫描`；失败项在列表中保留并高亮 rose 左边框。
- 全部成功且释放 < 50 MB：大数字换成 `缓存已经很干净`（24px）+ 副文案 `这次只释放了 42 MB`，不为一个无意义的数字庆祝。
- 关闭横幅（×）后回到普通结果态。
- 清理完成 **800ms 后自动重新扫描一次**，状态栏显示 `正在刷新缓存状态…`（小 spinner），保证列表体积是清理后的真实值；刷新失败则保留横幅和已有列表。
- 结果态下操作条恢复普通态（清空勾选、按钮禁用）。

### 2.8 错误态

- 扫描失败：`bg-rose-50 border border-rose-200 rounded-xl px-4 py-3 text-sm text-rose-700`，文案 `扫描失败：{message}`，右侧 `重试` 文字按钮。
- 清理整体失败（IPC 异常，非单项）：横幅换 rose 版本，标题 `清理失败`，正文 `未释放任何空间：{message}`，按钮 `重新扫描`。
- **不引入 toast**：沿用现有页面"区块内联提示"的做法（`tool-data-migrate` / `disk-heatmap` 均如此）。

## 3. 组件与视觉规范

### 3.1 颜色令牌

沿用 `globals.css`，新增的语义色全部走既有 Tailwind 色阶，不新建主题：

| 用途 | 值 / Tailwind | 说明 |
|---|---|---|
| 页面底 | 既有 body 渐变 | 不改 |
| 主卡 | `bg-[var(--card)]` `border-[var(--card-border)]` | 不改 |
| 分区 / 工具卡 | `bg-white/75` `border-slate-200` | 沿用 |
| 主操作（非破坏） | `var(--accent)` #11617d，hover #0d4d63 | 重新扫描、链接、焦点环 |
| 破坏性操作 | `bg-rose-600` / hover `rose-700` | **只用于清理按钮** |
| 安全 | 徽标 `bg-emerald-50 text-emerald-700 border-emerald-200`；横幅 `bg-emerald-50 border-emerald-200` | 可自动重建 |
| 谨慎 | 徽标 `bg-amber-50 text-amber-800 border-amber-200` | 会丢历史 |
| 危险 | 徽标 `bg-rose-50 text-rose-700 border-rose-300` | 需重新登录 / 可能丢数据 |
| 文本三级 | `slate-900` / `slate-600` / `slate-400` | 主 / 次 / 元信息 |
| 边框分隔 | `slate-200`，hover `slate-300` | |
| 工具身份色 | 复用 disk-heatmap 色板：Claude `#f3b15b`、Codex `#8cc98a`、Cursor `#7fa8d4`、其他 `#b8a894` | 仅 10px 圆点 + 3px 占比条 |

对比度：`slate-700` on white ≈ 10:1，`amber-800` on `amber-50` ≈ 7:1，`rose-700` on `rose-50` ≈ 6:1，均 ≥ 4.5:1。禁用态不靠低对比表达，同时给 `cursor-not-allowed` 与文案说明。

### 3.2 间距节奏

4px 基准，可用值 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40。

- 主卡：`p-6 sm:p-8`（同 tool-data-migrate）
- 区块纵向：`space-y-5`（20）
- 工具卡内：`p-4`；卡头 `px-4 py-3`；明细行 `px-4 py-3`（桌面行高 56px）
- 行内元素：`gap-3`（12）；统计块 `gap-3`；工具卡之间 12
- 控件高度：主按钮 / 输入框 40，次按钮 36，文字按钮 28
- 弹窗：header / body `p-5`，footer `px-5 py-4`

### 3.3 字号与字重

| 层 | 规格 |
|---|---|

### 3.4 圆角 / 阴影 / 边框

- 圆角：主卡 24（`rounded-3xl`）、工具卡与横幅 16（`rounded-2xl`）、行 / 输入 / 按钮 12（`rounded-xl`）、徽标 6（`rounded-md`）、占比条 full。
- 阴影：主卡沿用 `shadow-[0_24px_65px_-35px_rgba(17,97,125,0.55)]`；工具卡 `shadow-sm`；sticky 条上投影；弹窗 `shadow-[0_32px_80px_-24px_rgba(15,23,42,0.45)]`。
- 边框统一 1px；危险行左侧 3px `rose-300`；骨架块无边框色差。

### 3.5 动效（克制）

- 卡片入场：`opacity 0→1` + `translateY(4px→0)`，120ms ease-out，按索引 stagger 20ms（≤6 张卡）。
- 行 hover：背景 120ms；勾选切换立即生效（不做缩放/弹跳）。
- 操作条出现：上移 8px + 淡入，160ms。
- 进度条宽度：300ms ease-out。
- **不做结果数字 count-up**：清理结果要"立刻看到"，滚动数字会推迟反馈。
- 骨架：`animate-pulse`。
- `prefers-reduced-motion: reduce` 下关闭位移与入场，只保留颜色过渡。

### 3.7 可访问性 / 键盘

- 明细行用**原生 `input[type=checkbox]`** 保证 Space 可切换；行整体点击转发到 checkbox；行可 `role="checkbox"` 或 `label` 包裹（二选一，别同时用）。
- 弹窗：`role="dialog" aria-modal="true" aria-labelledby`，焦点陷阱，关闭后焦点回到「清理选中」按钮。
- 扫描 / 清理进度：`aria-live="polite"`，但**不要每 150ms 播报**，合并到秒级或阶段变化时播报。
- 可聚焦元素 `focus-visible:ring-2 ring-[var(--accent)]/40`。
- 颜色不是唯一信息载体：风险同时有文字（安全 / 谨慎 / 危险）。

## 4. 响应式

断点沿用 Tailwind：`sm` 640 / `md` 768 / `lg` 1024。

| 宽度 | 变化 |
|---|---|
| ≥1024 | 单列工具卡；明细行单行；操作条单行右对齐；弹窗居中 520px |
| 768–1023 | 同上；路径列 `max-width: 30%`；统计块保持 4 列 |
| 640–767 | 统计块 2 列；明细行两行：① 勾选 + 名称 + 风险 ② 路径 + 体积右对齐；操作条两行 |
| <640 | 工具卡 `rounded-xl`、`p-3`；卡头隐藏平台标签与「打开目录」文字（改 32px 纯图标按钮）；操作条按钮全宽 `h-11`；弹窗改底部 sheet：`items-end`、`rounded-t-2xl`、`max-h-[85vh]`、按钮竖排且危险按钮在上 |

- 设计基准尺寸 **1280×800**（截图验收用）；Tauri 桌面窗口最小建议 900×640。
- 关键动作始终可见：sticky 操作条在任意断点不被内容遮住，窄屏滚动时主卡底部保留 12px 安全距。
- 窄屏折叠：每组只展示前 3 行 + `展开全部 (5)` 文字按钮，避免长列表把操作条挤出视野。
- `lg` 以上不做多列卡片：分组卡内是横向明细表，两列会让路径和体积对齐跳来跳去，单列更好读。

## 6. 数据契约建议（供 Coder / Architect 对齐，非实现约束）

- `invoke("scan_ai_caches")` → `{ tools: ToolCacheGroup[], totalBytes, totalItems, scanDurationMs, scannedAt }`
- `ToolCacheGroup = { id, name, detected, platform, totalBytes, items: CacheItem[] }`
- `CacheItem = { id, label, path, sizeBytes, fileCount, risk: "safe" | "caution" | "danger", defaultSelected, description }`
- 扫描进度事件 `ai-cache-scan-progress`：`{ currentPath, toolsFound, itemsFound }`
- `invoke("clean_ai_caches", { itemIds })` → `{ freedBytes, items: [{ id, ok, error? }], durationMs }`
- 清理进度事件 `ai-cache-clean-progress`：`{ itemId, index, total, status: "running" | "ok" | "failed" }`
- **安全边界**：前端只传 `itemIds`，具体路径由后端白名单决定，前端不可传任意路径（与现有迁移工具一致）。
- **删除方式**：建议**直接删除、不进回收站**（进回收站等于没释放空间）；这也是确认弹窗必须强调"无法恢复"的原因。若后端改为回收站，确认文案须改为"已移入回收站"，结果文案改为"已移入回收站"。

## 7. 待确认项

1. **删除方式**：直接删除 vs 回收站 —— 决定"释放了多少空间"是否真实，建议直接删除。
2. **危险项边界**：登录凭据（`.credentials.json` / `auth.json`）是否纳入清理范围？建议纳入但默认不勾、单独 rose 区块确认。
3. **自定义扫描路径**：v1 建议不做（自动发现更简单，也避免用户误删非缓存目录）。
4. **扫描取消**：若后端无法中断，`取消` 只做前端忽略结果，进度文案需先显示 `正在停止…`。
5. **权限**：v1 只扫当前用户目录，不做系统级缓存、不请求提权。
6. **路径重叠**：多工具共享目录（如 `~/.cache`）的去重规则由后端保证，前端按 `item.id` 去重展示。
